## 현재 기획의 타당성과 한계

5개 화면으로 상담 준비용 예비 진단을 하는 것은 자연스럽습니다. 다만 매출·업종·자기평가 활용도만으로 제품 적합성이나 기업 레벨을 객관적으로 판정하는 근거는 이 자료에 없습니다. 원재료비·마진·ERP 구매 확률을 업종명에서 추정하지 않는 v2 방향을 유지하는 것이 합리적입니다.

소개서가 확인해 주는 것은 제품 기능의 **겹침과 차이**입니다. “회계=WEHAGO, 생산/프로젝트/분석=Amaranth, 맞춤=OmniEsol”은 이해하기 쉽지만 실제 선택을 지나치게 단순화합니다. WEHAGO 물류에는 생산/외주와 설계변경·가생산, WE PMS에는 예산·경비 연계·프로젝트 원가분석까지 소개돼 있습니다. 따라서 “단순 기능은 한 제품만, 깊은 기능은 다른 제품만” 같은 배타적 지원 여부는 해당 에디션에서 시연하기 전 확정하면 안 됩니다.

또한 5개 화면에 여러 하위 질문이 있어 실제 입력 항목은 5개보다 많습니다. 화면 수를 유지하되 추천과 관계가 약한 매출을 선택 정보로 남기고, 필요한 경우에만 후속 질문을 보여주는 편이 낫습니다.

## 제안: 5개 화면 + 선택 수요에 따른 후속 질문

| 화면 | 핵심 질문 | 후속 확인 / 활용 |
| --- | --- | --- |
| 1. 현재 환경 | 어떤 도구로 관리하고, 어디서 중복 입력·지연·오류가 생기나요? | 기존 불편 없음도 허용. 유지·교육·설정 개선 경로 확보 |
| 2. 실제 업무 | 어떤 업종이며 회계·물류·생산·프로젝트 중 실제로 수행하는 업무는 무엇인가요? | 업종은 예시와 상담 체크 항목만 변경. 로보틱스도 부품·생산이 없는 연구회사인지 구분 |
| 3. 기존 제품 | 제품명·에디션·사용 모듈과 해결되지 않는 업무는 무엇인가요? | 상중하는 참고용. 보유 모듈/설정·교육으로 해결 가능한지 우선 확인. 제품명을 모르거나 타 ERP라도 불이익 없음 |
| 4. 운영·도입 범위 | ERP 실제 사용 인원, 사업장/법인/통화, 필수 연계 시스템은 무엇인가요? | 임직원 수와 사용 인원 구분. 매출 비공개 허용. 예산·일정·책임자·데이터 정리는 선택형 상담 준비 정보 |
| 5. 필요한 기능의 깊이 | 반드시 시연해야 하는 업무는 무엇인가요? | **물류/생산:** 수발주·입출고 vs BOM/MRP·공정/외주·원가 배부. **프로젝트:** 일정·협업 vs 예산·경비·인건비 배부·손익. **문서/결재:** 별도 사용 vs ERP 거래/전표와 일체화. **분석/AI:** 정형 보고서 vs 자연어 조회·문서 근거 검색·초안·실행 지원. **연계:** 대상·방향·주기·건수·권한. 모름도 허용 |

5번의 모든 질문을 모두에게 노출하지 않습니다. 고른 기능에 해당하는 후속 질문만 표시하고, 기능의 지원 범위를 모르겠으면 비교 상담으로 연결합니다. 질문별 적절한 용어와 응답 시간은 실제 고객으로 검증해야 합니다.

## 제안하는 추천 분기 (공식 제품 선정 기준 아님)

1. 불편·추가 기능 없음 → 유지·점검. 신규 도입을 자동 권장하지 않음.
2. 기존 ERP 있음 → 보유 모듈·설정·교육·연계 개선 우선. 현재 제품명만으로 교체 확정하지 않음.
3. 회계·급여·세무와 필요한 개별 업무 서비스 → WEHAGO/Smart A 10 범위 시연. 물류·프로젝트 수요가 있어도 해당 서비스를 함께 확인.
4. ERP 거래·그룹웨어 결재·문서까지 연결하거나 생산·원가·프로젝트 흐름을 통합해야 함 → Amaranth 10 비교 후보. WEHAGO의 실제 지원/연계 범위와 차이를 요구사항별로 검증.
5. 확장 솔루션·다수 시스템 연계·전사 운영 플랫폼 요구 → Amaranth 10과 OmniEsol을 비교. DEWS/DIMS 필요성, 표준 설정 대안, 개발·운영 책임, 견적·라이선스 확인. 단순 보고서 수정만으로 OmniEsol을 자동 추천하지 않음.
6. 프로젝트 일정·예산·인력·원가 수요 → 현재 환경에 맞는 **WE PMS / Amaranth 10 PMS / 기존 제품 확장**을 구분. 모든 더존 고객에게 같은 PMS 자동 제안 금지.
7. AI → 사용 목적·문서/데이터·권한·검증 담당자·요금을 확인한 선택형 확장. 사용자의 요청에 따라 화면의 ONE AI는 Amaranth 10과 동반 제안하되, 타 제품에서는 사용할 수 없다는 의미로 표현하지 않음.
8. 정보 부족·답변 충돌 → 추가 확인. 모름을 낮은 점수로 바꾸거나 매출·업종으로 빈 정보를 보정하지 않음.

이 개편은 후속 질문의 새 응답 값, 공유 링크의 과거 버전 처리, 서버 계산·테스트를 함께 바꿔 적용해야 합니다. **상담에서 최종 선정된 후보와 진단 후보의 일치, 불필요한 교체 제안, 응답 완료율**을 수집해 규칙의 효과를 검증하고 이후 조정하는 것을 권합니다. 소개서만으로 정확도·공정성·도입 성과를 입증할 수는 없습니다.

## 이번에 반영한 것

- 4개 원본 PDF를 수정 없이 `brochures/`에 보관. 파일명은 영문으로 바꿔 URL 호환성 확보.
- 제품 카드마다 해당 PDF의 새 탭 보기·다운로드 제공. 용량/페이지 및 통합본 여부 표기. 이미지처럼 미리 불러오거나 iframe으로 자동 로딩하지 않음.
- ONE AI는 OmniEsol·ONE AI 통합본 7쪽으로 연결. 브라우저에 따라 `#page=7`을 지원하지 않으면 첫 페이지가 열릴 수 있어 페이지를 문구로도 안내.
- WEHAGO 두 문서는 각각 소개서/서비스 제안서로 연결. PMS 전용 첨부 PDF는 없어 관련 없는 문서를 붙이지 않고 공식 PMS 웹 안내 제공.
- WEHAGO·OmniEsol·ONE AI·PMS 설명을 자료에 맞게 보완. Amaranth 후보 결과에 WEHAGO 물류·WE PMS 범위도 비교하도록 안내와 PDF 링크 추가.
- 계산 규칙과 DB는 변경하지 않음. v3 제안은 미적용 상태이며, v2의 생산·프로젝트·분석 수요 통합 후보 분기는 여전히 예비 비교용임.
